
### 缺失的权限检查 ❌ 1. 文件只读属性检查 ❌
问题 ：内核没有检查文件本身的只读属性（如 FAT 文件系统中的 ATTR_READ_ONLY 标志）。

影响 ：

- 即使文件在文件系统中被标记为只读，内核仍然允许以写模式打开并修改该文件
- 这违反了文件系统的安全约束
建议位置 ：应该在 Filesys::Open 函数中添加检查，在打开文件进行写入之前检查 inode 的只读属性。
 2. 可执行权限检查 ❌
问题 ：内核在加载可执行文件（ELF）时，没有检查文件的可执行权限。

相关代码位置 ：

- taskman-new.cpp:620-637 - CreateFile 函数
- taskman-new.cpp:645-695 - Exec 函数
这些函数直接加载 ELF 文件，没有检查 i_mode 中的可执行位，这种情况允许，避免内核无法加载 init 等程序。

但是用户 syscall 执行这些二进制就应该检查了


在 filesys.hpp:53 中， i_mode 字段只定义了文件类型掩码：

```
#define I_TYPE_MASK     0170000
#define I_REGULAR       0100000
#define I_DIRECTORY     0040000
// ... 其他类型
```
缺失 ：

- 没有定义权限位（如 S_IRUSR , S_IWUSR , S_IXUSR 等）
- i_mode 字段没有存储实际的权限信息
### 总结

| 权限检查类型         | 状态       | 说明                            |
| -------------- | -------- | ----------------------------- |
| 打开模式检查         | ✅ 已实现    | 检查 O_RDONLY, O_WRONLY, O_RDWR |
| 写入权限检查         | ✅ 已实现    | 写操作前检查打开模式                    |
| O_TRUNC 权限     | ✅ 已实现    | 截断前检查写权限                      |
| O_DIRECTORY 检查 | ✅ 已实现    | 检查路径是否为目录                     |
| O_EXCL 检查      | ✅ 已实现    | 防止覆盖已存在的文件                    |
| **文件只读属性**     | ❌ **缺失** | 未检查文件系统层面的只读标志                |
| **可执行权限**      | ❌ **缺失** | 执行文件前未检查可执行位                  |
| **权限位定义**      | ❌ **缺失** | inode 未存储用户/组/其他权限位           |

### 建议改进
1. 扩展 i_mode 定义 ，添加权限位：
   
   ```
   #define S_IRUSR  0400  // 用户读权限
   #define S_IWUSR  0200  // 用户写权限
   #define S_IXUSR  0100  // 用户执行权限
   // ... 其他权限位
   ```
2. 在 Filesys::Open 中添加只读检查 ：
   
   ```
   // 检查文件只读属性
   if ((flags & O_ACCMODE) != O_RDONLY) {
       if (inode->i_mode & S_IRUSR && !(inode->i_mode & S_IWUSR)) {
           return -EACCES; // 权限拒绝
       }
   }
   ```
3. 在 Taskman::CreateFile 和 Exec 中添加可执行权限检查 ：
   
   ```
   if (!(inode->i_mode & S_IXUSR)) {
       plogerro("File not executable: %s", path);
       return nullptr;
   }
   ```
4. 从底层文件系统（如 FAT）读取文件属性 并映射到 i_mode 的权限位。
