

# 20260323 RISCV

|**维度**|**代码《1》（简易 OS / RTOS）**|**代码《2》（现代通用 OS 如 xv6）**|
|---|---|---|
|**运行特权级**|**Machine Mode (M-mode)** (最高权限)|**Supervisor Mode (S-mode)** (内核态) & U-mode (用户态)|
|**核心寄存器**|`mscratch`, `mepc`, `mret`|`sscratch`, `sepc`, `sret`|
|**内存管理**|**物理内存** (直接访问，通过 PMP 简单保护)|**虚拟内存** (操作 `satp` 寄存器切换页表)|
|**寄存器保存策略**|**一次性全量保存** (在 trap 发生时保存所有通用寄存器)|**分段保存** (Trap 保存用户态所有寄存器；`swtch` 只保存内核态被调用者保存寄存器)|
|**切换复杂度**|单层切换，直接在中断处理中换出下一个任务。|双层切换：先从用户态切到内核态，再在内核态切换内核线程。|

这段代码（从注释看可能来自某个 RISC-V OS MOOC）采用的是一种扁平化、轻量级的设计。

1. **M-Mode 直接接管一切**：系统直接运行在机器模式下。它初始化了栈，禁用了 PMP（允许访问所有物理内存），并将 `mstatus.MPP` 设为 3（确保 `mret` 后依然是 M 模式）。
2. **暴力且直接的上下文保存 (`reg_save` / `reg_restore`)**：
    - 一旦发生异常或中断，直接跳入 `trap_vector`。
    - 使用 `mscratch` 临时交换指针，把**所有**通用寄存器（包括调用者保存和被调用者保存的寄存器）全部压入当前任务的上下文中。
3. **单点任务切换 (`switch_to`)**：
    - 切换任务时，只需要改变 `mscratch`（指向新任务的上下文结构体）。
    - 恢复新任务的所有寄存器，加载 `mepc`，执行 `mret` 直接回到新任务被中断的地方。
    - **优点**：逻辑极其简单，上下文完全独立。
    - **缺点**：每次中断都要保存/恢复 30 个寄存器，开销较大；没有内存隔离，所有任务共享相同的物理地址空间。

这段代码是经典的 **xv6-riscv** 操作系统的进程切换核心代码。它引入了用户态/内核态隔离和虚拟内存。
1. **引入 Trampoline (蹦床机制) 与虚拟内存 (`satp`)**：
    - 在启用分页机制后，用户页表和内核页表是不同的。为了在切换页表的那一瞬间指令不至于跑飞，代码被放置在一个在用户空间和内核空间映射到**完全相同虚拟地址**的页面上（即 `trampoline`）。
    - 在 `uservec` 中，必须通过 `csrw satp, t1` 和 `sfence.vma` 切换到内核页表，才能继续执行内核 C 代码。
2. **两段式的上下文保存（极其优雅）**：
    - **第一步 (`uservec`)：用户态 -> 内核态。** 发生系统调用或中断时，把用户的 32 个通用寄存器全部保存到当前进程的 `TRAPFRAME` 中。此时 CPU 进入了该进程的内核栈。
    - **第二步 (`swtch`)：内核态 -> 内核态。** 当内核决定要调度（比如时间片用完）时，它会调用 C 函数 `swtch`。重点来了：**`swtch` 只保存 14 个寄存器**（`ra`, `sp`, `s0-s11`）。为什么不保存 `t0-t6` 或 `a0-a7`？因为 `swtch` 是一个标准的 C 函数调用，按照 RISC-V ABI 规范，C 语言编译器在调用函数前，**已经自动把调用者保存的寄存器压入内核栈了**。所以汇编层面只需要保存“被调用者保存（Callee-saved）”的寄存器即可。
3. **返回用户态 (`userret`)**：
    - 从调度器切回当前进程的内核线程后，最终会调用 `userret`，切换回用户页表，恢复 `TRAPFRAME` 里的用户态寄存器，通过 `sret` 回到用户空间。

---

把这两个结合起来。在 Machine Mode (M-mode) 实现有分页的、普适于M/S/U程序的调度设计。

这是一个非常硬核且极具前瞻性的想法！将代码《1》（M模式下的直接控制）与代码《2》（虚拟内存与权限隔离）结合起来，意味着你想要设计一个**运行在最高特权级 (M-mode) 的微内核 (Microkernel) 或轻量级 Hypervisor**。

在这个架构中
- **内核代码运行在 M-mode**，使用**物理地址**（不受 `satp` 影响）。
- **用户程序 (U-mode) 或客户操作系统 (S-mode)** 运行在**虚拟地址**空间，由 `satp` 寄存器指定的页表进行地址翻译。

相比于 xv6（S-mode 调度），M-mode 调度有一个**巨大的天然优势**：M 模式默认使用物理地址。这意味着当 U/S 模式发生异常陷入 M 模式时，CPU 会直接跳到物理内存中的 `mtvec` 地址，**你完全不需要像 xv6 那样设计复杂的“蹦床 (Trampoline)”页面**！
