alloc_stack：分配私有栈
协程必须有自己的栈空间。在 RISC-V 中，栈是向低地址增长的。

```
pub fn alloc_stack() -> (Vec<u8>, usize) {
    let buf = vec![0u8; STACK_SIZE];
    let top = buf.as_ptr() as usize + STACK_SIZE;
    // RISC-V ABI 要求栈顶必须 16 字节对齐
    let aligned_top = top & !0xf;
    (buf, aligned_top)
}
```

TaskContext::init：伪造初始状态
我们要让一个刚创建的协程看起来像是“正要从某个函数返回”。

```
pub fn init(&mut self, stack_top: usize, entry: usize) {
    // 设置返回地址为入口函数。这样当 switch_context 执行 ret 时，会跳转到 entry。
    self.ra = entry as u64;
    // 设置栈指针。
    self.sp = stack_top as u64;
}
```

```
#[unsafe(naked)]
pub unsafe extern "C" fn switch_context(_old: &mut TaskContext, _new: &TaskContext) {
    core::arch::naked_asm!(
        // 1. 保存当前（旧）任务的寄存器到 a0 指向的地址
        "sd sp, 0(a0)",
        "sd ra, 8(a0)",
        "sd s0, 16(a0)",
        "sd s1, 24(a0)",
        "sd s2, 32(a0)",
        "sd s3, 40(a0)",
        "sd s4, 48(a0)",
        "sd s5, 56(a0)",
        "sd s6, 64(a0)",
        "sd s7, 72(a0)",
        "sd s8, 80(a0)",
        "sd s9, 88(a0)",
        "sd s10, 96(a0)",
        "sd s11, 104(a0)",

        // 2. 从 a1 指向的地址加载新任务的寄存器
        "ld sp, 0(a1)",
        "ld ra, 8(a1)",
        "ld s0, 16(a1)",
        "ld s1, 24(a1)",
        "ld s2, 32(a1)",
        "ld s3, 40(a1)",
        "ld s4, 48(a1)",
        "ld s5, 56(a1)",
        "ld s6, 64(a1)",
        "ld s7, 72(a1)",
        "ld s8, 80(a1)",
        "ld s9, 88(a1)",
        "ld s10, 96(a1)",
        "ld s11, 104(a1)",

        // 3. 返回。此时 ra 已经是新任务的地址了。
        "ret"
    );
}
```

在 `#[unsafe(naked)]` 函数中，Rust 编译器不允许你在汇编代码之外使用任何 Rust 语句（包括 `todo!()`）。编译器之所以报 `unused variable`，是因为在汇编代码里，参数是通过寄存器（`a0`, `a1`）直接访问的，而编译器“看不见”汇编里的引用，所以它觉得你没用这两个参数。

extern "C" ：在 Rust 中，如果你不指定函数的 ABI，它默认使用 extern "Rust"。但 Rust 官方规定：#[naked] 只能用于具有稳定调用约定（ABI）的函数。

# 用户态协作式调度器“绿线程”（Green Threads）

调度器的本质是一个**管理机构**。它维护一个线程列表，决定现在谁在运行，谁在排队。

- **主线程 (Main Thread)**：它是 `threads[0]`。当你在 `main` 函数里调用 `sched.run()` 时，主线程进入调度循环。
- **绿线程 (Green Thread)**：由 `spawn` 创建。每个线程有自己的栈（`Vec<u8>`）和寄存器快照（`TaskContext`）。
- **协作式 (Cooperative)**：线程必须**主动**调用 `yield_now()` 才会交出 CPU。这不同于内核的“抢占式”调度（靠时钟中断强行切换）。

```
pub fn spawn(&mut self, entry: extern "C" fn()) {
    // 1. 分配栈内存
    let mut stack = vec![0u8; STACK_SIZE];
    let stack_top = stack.as_ptr() as usize + STACK_SIZE;
    
    // 2. 初始化上下文
    let mut ctx = TaskContext::default();
    // ra = thread_wrapper: 第一次切到这个线程时，它会从 wrapper 开始执行
    ctx.ra = thread_wrapper as u64;
    // sp = 16字节对齐。减 16 是为了留出一点初始调用栈的余量
    ctx.sp = ((stack_top - 16) & !15) as u64;

    // 3. 加入就绪队列
    self.threads.push(GreenThread {
        ctx,
        state: ThreadState::Ready,
        _stack: Some(stack),
        entry: Some(entry),
    });
}

pub fn run(&mut self) {
    // 1. 设置全局指针，方便 yield_now 找到调度器
    unsafe { SCHEDULER = self as *mut Scheduler };

    // 2. 调度循环：只要还有用户线程没跑完，就一直切
    // threads[1..] 是用户创建的线程
    while self.threads[1..].iter().any(|t| t.state != ThreadState::Finished) {
        self.schedule_next();
    }

    // 3. 清理环境
    unsafe { SCHEDULER = core::ptr::null_mut() };
}

fn schedule_next(&mut self) {
    let old_idx = self.current;
    let len = self.threads.len();

    // 1. 轮询 (Round-Robin) 寻找下一个 Ready 线程
    let mut next_idx = (old_idx + 1) % len;
    while self.threads[next_idx].state != ThreadState::Ready {
        next_idx = (next_idx + 1) % len;
        // 如果转了一圈发现没有 Ready 的（比如都在 Finished 或正在 Running），直接返回
        if next_idx == old_idx { return; }
    }

    // 2. 更新状态
    if self.threads[old_idx].state == ThreadState::Running {
        self.threads[old_idx].state = ThreadState::Ready;
    }
    self.threads[next_idx].state = ThreadState::Running;
    self.current = next_idx;

    // 3. 如果是该线程第一次运行，设置全局入口函数给 thread_wrapper 看
    if let Some(entry) = self.threads[next_idx].entry.take() {
        unsafe { CURRENT_THREAD_ENTRY = Some(entry) };
    }

    // 4. 执行上下文切换
    unsafe {
        // 这里必须拿到两个指针，直接调用 switch_context
		// 1. 先通过索引拿到两个线程的原始指针 
		// 这不会触发借用检查器的独占锁 
		let old_ptr = &mut self.threads[old_idx] as *mut GreenThread; 
		let new_ptr = &self.threads[next_idx] as *const GreenThread; 
		// 2. 从原始指针访问字段并调用 switch 
		// 注意：这里的 (*ptr) 需要在 unsafe 块内
		switch_context(&mut (*old_ptr).ctx, &(*new_ptr).ctx);
    }
}
```

我们在 `TaskContext` 上标记了 `#[repr(C)]`。如果没这个标记，Rust 编译器可能会重排字段顺序，导致汇编代码里的 `sd sp, 0(a0)` 写到了 `ra` 的位置，从而引发极其难排查的内存错误。

初学者容易困惑的地方：**为什么不直接把 `ra` 设为 `entry`？**

- **生命周期管理**：如果直接调用 `entry()`，当函数返回时，CPU 会去读一个随机的返回地址，导致崩溃。
- **自动化操作**：`thread_wrapper` 负责在用户函数执行完后，自动调用 `thread_finished()`。这个函数会将线程状态改为 `Finished` 并切回调度器。
- **C++ 类比**：这就像 `std::thread` 的构造函数内部会封装一层，用来处理异常捕获和线程局部变量的清理。
