
又名 no_std 编程

**原始指针（Raw Pointers）**：
- `*const u8`：常量原始指针（类似于 `const uint8_t*`）。
- `*mut u8`：可变原始指针（类似于 `uint8_t*`）。
    

**关键规则**：
1. **Unsafe**：操作原始指针必须在 `unsafe` 块中进行，因为编译器无法保证指针是否合法。
2. **指针算术**：不能像 C 一样直接 `ptr++`。必须使用 `ptr.add(i)` 或 `ptr.offset(i)`。
3. **No Mangle**：`#[unsafe(no_mangle)]` 告诉编译器不要混淆函数名，这样链接器（比如 C 语言代码）就能通过名字 `my_memcpy` 找到这个函数。

### 常用函数

```
pub unsafe extern "C" fn my_memcpy(dst: *mut u8, src: *const u8, n: usize) -> *mut u8 {
    for i in 0..n {
        // 使用 .add(i) 获取偏移后的指针，再用 * 进行解引用（读/写）
        unsafe {
            *dst.add(i) = *src.add(i);
        }
    }
    dst
}

pub unsafe extern "C" fn my_memset(dst: *mut u8, c: u8, n: usize) -> *mut u8 {
    for i in 0..n {
        unsafe {
            *dst.add(i) = c;
        }
    }
    dst
}

pub unsafe extern "C" fn my_memmove(dst: *mut u8, src: *const u8, n: usize) -> *mut u8 {
    if dst == src as *mut u8 || n == 0 {
        return dst;
    }

    // 检查是否需要倒序拷贝：dst 指针在 src 之后，且距离小于 n
    if dst > src as *mut u8 && (dst as usize) < (src as usize + n) {
        // 从后往前拷
        let mut i = n;
        while i > 0 {
            i -= 1;
            unsafe {
                *dst.add(i) = *src.add(i);
            }
        }
    } else {
        // 正常从前往后拷（调用我们写好的 memcpy）
        my_memcpy(dst, src, n);
    }
    dst
}

pub unsafe extern "C" fn my_strlen(s: *const u8) -> usize {
    let mut len = 0;
    // 只要当前字符不是 0，就继续
    while unsafe { *s.add(len) } != 0 {
        len += 1;
    }
    len
}

pub unsafe extern "C" fn my_strcmp(s1: *const u8, s2: *const u8) -> i32 {
    let mut i = 0;
    loop {
        let c1 = unsafe { *s1.add(i) };
        let c2 = unsafe { *s2.add(i) };

        if c1 != c2 || c1 == 0 {
            return (c1 as i32) - (c2 as i32);
        }
        i += 1;
    }
}
```

# Bump Allocator（堆栈式分配器）

是所有内存分配器中最简单、最快的一种，常用于操作系统内核启动初期，或者生命周期极短的任务场景。

作为 C++ 程序员，你可以把它想象成一个只管往后移动的指针，就像 `std::vector` 的 `push_back` 逻辑，但它分配的是原始内存，且**不支持 `dealloc`（释放）**（除非全部重置）。

```
unsafe impl GlobalAlloc for BumpAllocator {
    unsafe fn alloc(&self, layout: Layout) -> *mut u8 {
        // 1. 获取当前分配点的快照
        let mut current_next = self.next.load(Ordering::SeqCst);

        loop {
            // 2. 计算对齐后的起始地址
            let align = layout.align();
            let size = layout.size();
            
            // align_up 公式实现
            let alloc_start = (current_next + align - 1) & !(align - 1);
            
            // 3. 计算结束地址
            let alloc_end = match alloc_start.checked_add(size) {
                Some(end) => end,
                None => return null_mut(), // 溢出
            };

            // 4. 边界检查：是否超过堆末尾
            if alloc_end > self.heap_end {
                return null_mut(); // OOM (Out of Memory)
            }

            // 5. 原子更新 (CAS)
            // 尝试将 next 从 current_next 更新为 alloc_end
            match self.next.compare_exchange_weak(
                current_next,
                alloc_end,
                Ordering::SeqCst,
                Ordering::SeqCst,
            ) {
                Ok(_) => {
                    // 成功！返回对齐后的起始地址
                    return alloc_start as *mut u8;
                }
                Err(actual_next) => {
                    // 失败！说明别的线程抢先分配了内存。
                    // actual_next 是最新的 next 值，更新它并重试循环。
                    current_next = actual_next;
                }
            }
        }
    }

    unsafe fn dealloc(&self, _ptr: *mut u8, _layout: Layout) {
        // Bump 分配器不支持回收单个对象。
        // 就像你在白纸上写字，只能整页擦除（reset），不能擦掉中间的一个词。
    }
}
```

 `GlobalAlloc` 特质

一旦你为一个结构体实现了 `GlobalAlloc`，你就可以通过 `#[global_allocator]` 把它设置成整个程序的堆管理器。这样，当你使用 `Box::new` 或 `Vec` 时，底层就会调用你写的这个 `alloc` 函数。

# 空闲链表分配器 (Free-List Allocator)

在之前的 Bump Allocator 中，我们只能“只进不出”。而 Free-List Allocator 引入了**回收机制**。它维护一个链表，记录所有被释放的内存块。下次分配时，先去链表里找，找不到了再动用底部的备用内存（Bump region）。

**相关实现** uni.MemoryPool

---

```
struct FreeBlock {
    size: usize,
    next: *mut FreeBlock,
}
```

它并不额外占用内存，而是直接**存储在被释放的内存空间头部**。这意味着每个分配出的内存块大小至少要能塞下一个 `FreeBlock`。

释放内存时，我们不把内存还给系统，而是把它挂在链表的头部（头插法）。

```
unsafe fn dealloc(&self, ptr: *mut u8, layout: Layout) {
    // 1. 确保块大小足够存下 Header
    let size = layout.size().max(core::mem::size_of::<FreeBlock>());
    
    // 2. 将原始指针转为 Header 指针
    let new_node_ptr = ptr as *mut FreeBlock;
    
    // 3. 构造新的节点，并让它指向当前的链表头
    let new_node = FreeBlock {
        size,
        next: self.free_list_head(),
    };
    
    // 4. 将 Header 信息写入内存
    new_node_ptr.write(new_node);
    
    // 5. 更新链表头为当前新释放的块
    self.set_free_list_head(new_node_ptr);
}
```

分配逻辑变为：**先搜链表，搜不到再 Bump**。

```rust
unsafe fn alloc(&self, layout: Layout) -> *mut u8 {
    let size = layout.size().max(core::mem::size_of::<FreeBlock>());
    let align = layout.align().max(core::mem::align_of::<FreeBlock>());

    // --- Step 1: 遍历链表 (First-Fit 策略) ---
    let mut prev_ptr: *mut *mut FreeBlock = &mut self.free_list_head(); // 这里逻辑略复杂，为了修改指针需要拿到指针的地址
    let mut current = self.free_list_head();

    // 实际练习中由于 set_free_list_head 的封装，我们手动处理遍历
    let mut prev: *mut FreeBlock = null_mut();
    let mut curr = self.free_list_head();

    while !curr.is_null() {
        let block = &*curr;
        // 检查地址是否对齐，且空间是否足够
        if curr as usize % align == 0 && block.size >= size {
            // 找到了！从链表中移除
            let next_node = block.next;
            if prev.is_null() {
                self.set_free_list_head(next_node);
            } else {
                (*prev).next = next_node;
            }
            return curr as *mut u8;
        }
        prev = curr;
        curr = block.next;
    }

    // --- Step 2: 链表没找到，使用 Bump 分配 ---
    let mut current_next = self.bump_next.load(core::sync::atomic::Ordering::SeqCst);
    loop {
        let alloc_start = (current_next + align - 1) & !(align - 1);
        let alloc_end = match alloc_start.checked_add(size) {
            Some(end) => end,
            None => return null_mut(),
        };

        if alloc_end > self.heap_end {
            return null_mut();
        }

        match self.bump_next.compare_exchange_weak(
            current_next,
            alloc_end,
            core::sync::atomic::Ordering::SeqCst,
            core::sync::atomic::Ordering::SeqCst,
        ) {
            Ok(_) => return alloc_start as *mut u8,
            Err(actual) => current_next = actual,
        }
    }
}
```


这个简单的实现会产生严重的**外部碎片**。
- **原因**：我们在 `alloc` 时如果找到了一个 1024 字节的块，即使只申请 32 字节，也会把整个 1024 字节块拿走（或者只剩一丁点没法利用）。
- **进阶方案**：真正的分配器（如 `dlmalloc`）会执行 **Split（拆分）** 操作，把大块拆成“刚好够用的块 + 剩下的空闲块”。

在 `dealloc` 时检查物理相邻的块并 **Merge（合并）**。

```
pub unsafe fn syscall3(id: usize, arg0: usize, arg1: usize, arg2: usize) -> isize {
    let ret: isize;
    core::arch::asm!(
        "syscall",
        inlateout("rax") id => ret, // 输入是 id，结束后 rax 存返回值 ret
        in("rdi") arg0,
        in("rsi") arg1,
        in("rdx") arg2,
        out("rcx") _, // 告知编译器 rcx 被破坏了
        out("r11") _, // 告知编译器 r11 被破坏了
    );
    ret
}

        inlateout("x0") arg0 => ret, // 第一个参数和返回值都在 x0
        in("x1") arg1,
        in("x2") arg2,
    );
    ret
```

Rust 的条件编译非常强大且常用。在 C++ 中你会用大量的 `#ifdef __x86_64__`。Rust 的属性语法更整洁，且能够应用在函数、结构体、甚至模块级别。

 `inlateout` 与 寄存器控制

在 C++ 的 `asm` 中，你可能需要手动编写约束符如 `"=a"`。 Rust 的 `asm!` 宏非常直观：
- `in("reg")`：数据进入寄存器。
- `out("reg") _`：寄存器被修改了，我不关心结果（下划线表示抛弃）。
- `inlateout("reg") val => ret`：这是一个优化，告诉编译器“输入用这个寄存器，一旦指令执行完，**立即**从这个寄存器读出返回值”。

返回 `!` 类型
`sys_exit` 的返回类型是 `!`（Never type）。这告诉编译器该函数**绝对不会返回**。这在 C++ 中通常需要 `[[noreturn]]` 属性。在 Rust 中，它是类型系统的一等公民，有助于编译器进行更准确的控制流分析。

# **文件描述符表（File Descriptor Table）**。

在 Linux 中，“一切皆文件”。不管是磁盘上的文件、管道（Pipe）、还是网络套接字（Socket），对用户程序来说都只是一个整数（FD）。内核内部则通过这个表，把整数映射到真正的文件对象上。

`Arc<dyn File>`：多态与共享

- **`dyn File`**：这是一个**特质对象（Trait Object）**。它告诉 Rust：“我不关心具体是什么类型，只要它实现了 `File` 接口就行”。这在 C++ 中对应**虚函数/抽象基类**。
- **`Arc<T>`**：原子引用计数。因为多个 FD 可能指向同一个文件（比如 `dup()` 系统调用），或者文件正在被多个线程访问，所以我们需要引用计数来管理生命周期。这对应 C++ 的 `std::shared_ptr`。
    

`Vec<Option<...>>`：稀疏表

文件描述符通常是从 0 开始的连续整数。如果用户关闭了 `fd=1`，我们会把索引 1 的位置设为 `None`，产生一个“空洞”。下次分配时，我们会优先填补这个空洞。

```
pub struct FdTable {
    // 使用 Option 来表示该位置是否被占用
    files: Vec<Option<Arc<dyn File>>>,
}

impl FdTable {
    pub fn new() -> Self {
        Self { files: Vec::new() }
    }

    /// 分配新的 FD：优先找最小的空位，找不到了再拓宽 Vec
    pub fn alloc(&mut self, file: Arc<dyn File>) -> usize {
        // 1. 尝试寻找最小的 None 位置
        if let Some(fd) = self.files.iter().position(|slot| slot.is_none()) {
            self.files[fd] = Some(file);
            fd
        } else {
            // 2. 如果没有空位，直接推入末尾
            let fd = self.files.len();
            self.files.push(Some(file));
            fd
        }
    }

    pub fn get(&self, fd: usize) -> Option<Arc<dyn File>> {
        // 使用 get() 自动处理越界检查，然后用 flattened 展开 Option
        self.files.get(fd)?.clone()
    }

    pub fn close(&mut self, fd: usize) -> bool {
        // 如果索引在范围内且内容是 Some，则用 None 替换它
        if fd < self.files.len() && self.files[fd].is_some() {
            self.files[fd] = None;
            true
        } else {
            false
        }
    }

    pub fn count(&self) -> usize {
        // 计算非 None 的元素数量
        self.files.iter().flatten().count()
    }
}
```
